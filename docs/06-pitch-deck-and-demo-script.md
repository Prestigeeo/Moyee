### SLIDE 6: Under the Hood — Our Trust & Anti-Hallucination Architecture (5:30 – 6:45)

#### On-Screen Visual (Architecture Diagram)
- **Hybrid Reciprocal Rank Fusion (RRF) Retrieval:** Combines lexical overlap + subword 4-gram semantic cosine similarity (`k=60`) with **Cross-Paper Diversity** so multi-paper trend questions always pull evidence from across the library.
- **Multi-Provider Self-Healing AI Gateway:** `Google Gemini 3 Flash` → automatic failover to `Groq 120B (openai/gpt-oss-120b)` → `Local Ollama` → `Deterministic Extractive Fallback`.
- **Zero-Trust Citation Verifier:**
  - Prompts wrap document chunks in `<source id="S1" location="p. 12">` tags with strict prompt-injection sandboxing.
  - Post-generation regex verifier strips any `[S#]` marker that does not map to a real database chunk ID.
  - Separate **Evidence Layer** (verbatim quotes + page links) from **Interpretation Layer**.

#### Speaker Script (1 Minute 15 Seconds)
> "How do we guarantee that Móyee doesn't hallucinate like general chatbots? We engineered a three-layer trust architecture:  
> First, our retrieval engine uses **Hybrid Reciprocal Rank Fusion** with cross-paper source diversity, ensuring that when you ask for common trends across 5 papers, the retriever balances passages across all 5 sources.  
> Second, our **Multi-Provider AI Gateway** routes requests through Google’s `Gemini 3 Flash`, with automatic sub-second failover to `Groq 120B`, local `Ollama`, or a deterministic extractive fallback—meaning Móyee has **zero downtime**.  
> Third—and most importantly—our **Citation Verifier** validates every `[S#]` citation marker against the actual PostgreSQL chunk ID and page number before the user ever sees it. If a source doesn't report a sample size or limitation, Móyee explicitly writes `'Not reported'` instead of guessing."
